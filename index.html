    LAKELOOM / GUIDE
    Product documentation.
    Build, review, preview, and export a reusable PySpark notebook from one workspace.
    
            
    ✦
    Quick start
    Choose a source, inspect its columns, select transformations in execution order, review the generated PySpark, then preview or export the notebook.
    
            
    
              
    01
    Choose a source
    Select Files for CSV, JSON, TXT, Parquet, Avro, or ORC; Table folder for Delta or Iceberg directories; or Databricks for a catalog table or storage path.
    • Local file formats are detected automatically.
    • Enter the Databricks path that the generated notebook will read.
    • Selected local files are inspected for schema and are not uploaded to Databricks.
    
              
    02
    Inspect the schema
    Choose a file or folder and use the source inspection action. LakeLoom displays available columns and their Spark SQL types.
    • Unknown transformation columns are highlighted.
    • Reinspect after replacing the local source.
    • Use Load from Databricks when the source is available only in your workspace.
    
              
    03
    Select transformations
    Search or browse the transformation library. Select steps in the order they should run and complete the settings shown inside each selected card.
    • Hover dropdowns and read the explanation under the selected option.
    • Uncheck and reselect a step to change its execution position.
    • The live preview updates as settings change.
    
              
    04
    Flatten nested JSON
    Choose the method that matches the source type.
    • Structs only: enter a path such as order.item.details.
    • Single array: explode one array and optionally expand struct fields.
    • Multiple arrays: add ordered mappings such as orders -> order and order.items -> item, then list the leaf fields to select.
    
              
    05
    Create more DataFrames
    Select Continue in a new DataFrame where a pipeline boundary is required.
    • Choose Current result to continue previous transformations.
    • Choose Original source to begin again from the input DataFrame.
    • Add more DataFrame steps for names such as df_next and df_part.
    
              
    06
    Configure output
    Enable the write step and choose Delta, CSV, JSON, TXT, Parquet, Avro, ORC, or Iceberg.
    • Set the Databricks destination and write mode.
    • Add partition columns only when they improve downstream reads.
    • Review format-specific settings such as CSV headers and compression.
    
              
    07
    Preview with Databricks
    Connect through Databricks Apps or a configured Databricks Connect profile. Run preview executes the generated notebook against the connected workspace and displays a limited result.
    • Review the code before running it.
    • Use Edit code for manual adjustments.
    • Reset code to regenerate it from the selected options.
    
              
    08
    Export the notebook
    Click Export notebook and choose a format. The download begins immediately.
    • Databricks source: .py
    • Jupyter: .ipynb
    • Plain text, Markdown, HTML, or Print / Save as PDF
    
              
    09
    Save and reuse recipes
    Save the current source, transformations, and output settings as a recipe. Open Saved recipes to restore or delete a configuration.
    • Recipes are stored in the current browser.
    • Source file contents are not stored in a recipe.
    • Verify paths before running a restored recipe.
    
              
    10
    Review activity
    Run history records local notebook exports and recipe changes. Databricks execution status requires a connected backend.
    • Use Clear history to remove local entries.
    • Browser data is specific to the current browser profile.
    • Report problems through the footer issue link.
    
            
    
            
    
              
    REFERENCE
    Transformation guide
    Choose the smallest set of steps that produces the required result. Steps execute in their selected order.
    
              
    CategoryUse it forCommon operations and guidance
    
                
    Select & shapeControl DataFrame columns and structure.Select required fields early for wide sources. Create, rename, remove, and standardize columns.
    
                
    Data qualityRepair missing or duplicate records.Handle nulls, distinct rows, duplicate keys, and latest records. Use stable key and timestamp columns.
    
                
    Filter & sortRestrict or order records.Use PySpark or SQL conditions. Wrap combined PySpark conditions in parentheses when using & and |.
    
                
    ExpressionsCreate business fields and clean values.Calculated columns, classifications, text cleanup, regex, arrays, maps, and JSON functions.
    
                
    DatesParse, format, compare, and shift dates.Use Spark patterns such as yyyy-MM-dd and confirm they match the input text.
    
                
    AnalyticsSummarize data or calculate within groups.Group, aggregate, pivot, rank, and cumulative totals. Choose partition keys carefully.
    
                
    Complex typesWork with arrays, maps, structs, and JSON.Explode arrays, parse JSON strings with a schema, and flatten nested fields.
    
                
    DataFrame toolsPreserve intermediate pipelines.Continue from the current result or original source. DataFrame assignments are lazy and do not copy data.
    
                
    Delta & SCDMaintain Delta tables and history.SCD Type 1 and 2, inspect, compare, delete, restore, and vacuum. Verify targets and permissions first.
    
              
    
            
    

            
    
              
    EXAMPLE
    Flatten multiple JSON array levels
    Use an ordered explode plan when one array contains structs that contain another array.
    
              
    
                
    Array expansion plan
    orders -> order
order.items -> item
    Each output alias becomes available to the following line. Renaming an alias updates dependent paths in the form.
    
                
    Output field plan
    user_id
address.city -> city
order.order_id -> order_id
item.product_id -> product_id
item.quantity -> quantity
    Use path -> alias when the output name should differ from the source leaf name.
    
              
    
              
    Generated PySpark pattern
    df = (
    df
    .withColumn("order", F.explode(F.col("orders")))
    .withColumn("item", F.explode(F.col("order.items")))
    .select(
        F.col("user_id"),
        F.col("address.city").alias("city"),
        F.col("order.order_id").alias("order_id"),
        F.col("item.product_id").alias("product_id")
    )
)
    
            
    

            
    
              
    DELTA LAKE
    SCD and table operations
    These actions can change a Delta target. Review the generated code and target before running it.
    
              
    
                
    SCD Type 1
    Keeps one current row per business key. Matching records are updated and new records are inserted; previous values are not retained.
    
                
    SCD Type 2
    Preserves history by expiring the current record and inserting a new version with valid-from, valid-to, and current-row fields.
    
                
    Inspect and compare
    Review table history or metadata and compare two versions with distinct or duplicate-preserving differences.
    
                
    Restore, delete, and vacuum
    Restore returns to a prior version, delete removes matching rows, and vacuum removes old files after retention.
    
              
    
            
    

            
    
              
    ENGINEERING MODULES
    Build production data pipelines
    These modules add validation, observability, reusable configuration, and multi-DataFrame workflows to the generated notebook.
    
              
    
                
    Profile data
    Measures row counts, null counts, distinct values, and descriptive statistics. Profile before and after important transformations to understand their effect.
    
                
    Data quality rules
    Enter validation expressions to separate valid and failed rows. Failed records include the rule names so users can diagnose each problem.
    
                
    Join DataFrames
    Read a lookup or fact table and join it using mapped keys and the selected join type. Select only required columns before large joins where possible.
    
                
    Branch and reject records
    Create named DataFrames from matching and nonmatching rows, or route invalid records to a rejected DataFrame with a reason column.
    
                
    Schema evolution
    Compare source and target schemas before writing. For Delta output, merge mode also generates the mergeSchema writer option.
    
                
    Parameters and environments
    Create Databricks widgets for values such as environment, catalog, dates, or paths. One exported notebook can then run with different settings.
    
                
    Incremental loading
    Filter with a watermark column or read Delta Change Data Feed from a starting version. Use checkpoints or a control table to persist progress in an orchestrated job.
    
                
    Monitoring
    Creates a run ID, UTC timestamp, status, and row-count metrics DataFrame that can be displayed or written to an audit target.
    
                
    Generated tests
    Adds assertions for required columns, null values, unique keys, and minimum row counts. Run these before writes or SCD operations.
    
                
    Recipe portability
    Export saved recipes as JSON and import them into another browser. Source files remain local and are never included in the recipe file.
    
              
    
            
    

            
    
              
    PIPELINE TOOLS
    Inspect and improve before export
    The builder provides immediate feedback while you configure the notebook.
    
              
    
                
    Visual pipeline
    Shows the source, every selected transformation in execution order, and the final preview or output. Uncheck and reselect a step to change its position.
    
                
    Step preview
    Select a step and run only the pipeline through that point. This helps locate the transformation where rows or columns first change unexpectedly.
    
                
    Performance advisor
    Flags common structural costs such as sorting before filtering, wide joins, array explosions, large window shuffles, and long unnamed pipelines.
    
                
    Pipeline assistant
    Describe a goal in plain language and LakeLoom suggests matching transformations. The assistant runs locally with keyword rules; review generated settings and expressions before execution.
    
              
    
            
    

            
    
              
    TROUBLESHOOTING
    Common questions
    
              
    
                
    Why is a column highlighted as unknown?
    The column is unavailable at that position in the selected order. Check spelling, reinspect the source, or move the step after the transformation that creates it.
    
                
    Why does a nested array fail in the struct input?
    The optional nested field input expands structs only. Select Multiple array levels and add each array path to the explode plan.
    
                
    Why is a Databricks path required for a local file?
    The local file is used for schema inspection. The exported notebook runs in Databricks and needs a table or storage path available there.
    
                
    Why is Run preview unavailable?
    Configure Databricks Connect or run LakeLoom as a Databricks App with workspace authentication and source permissions.
    
                
    Do new DataFrame steps duplicate data?
    No. Spark DataFrames are lazy query plans. Assigning a new variable does not execute, copy, cache, or checkpoint the data.
    
                
    Where are recipes and history stored?
    They are stored in the current browser profile. They do not automatically transfer to another browser or device.

    PREVIEW
    Preview troubleshooting
    
              
    Why is Run preview disabled?
    LakeLoom did not find a Databricks profile, the workspace session is missing, or the pipeline contains a Delta management or SCD action that is blocked from read-only preview.
    Why can I connect but not read a table?
    Your Databricks user needs permission to use serverless compute and read the catalog, schema, table, volume, or external location entered as the source.
    Can preview run completely offline?
    No. Building, schema inspection for local files, recipes, code generation, and export work offline. PySpark execution uses Databricks compute.
    
            
    
            
    
              
    SOURCES
    Files, schemas, and nested JSON
    
              
    Why do I enter a Databricks path after choosing a local file?
    The browser file is used for schema inspection. The generated notebook needs the equivalent workspace path, such as a Unity Catalog Volume path, when it runs.
    How do I read multiline JSON?
    JSON sources generate a single reader statement with .option("multiline", "true").
    How do I flatten several array levels?
    Choose Multiple array levels and enter steps in order, for example orders -> order and then order.items -> item.
